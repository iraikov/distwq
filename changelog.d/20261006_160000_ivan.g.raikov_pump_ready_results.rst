Fixed
-----

- ``as_completed()``, ``wait()`` and ``DistributedFuture.result()`` no
  longer hang when the result they wait for was already received by the
  controller, for instance while a later ``submit()`` handled incoming
  messages.  The controller now delivers the results it holds before it
  waits in a blocking probe for the next message, so callers no longer
  need to call ``wait(futures, timeout=0)`` first.
